## General caveats

- **ATSP mapping**: ELM327 `ATSP6/7` = ISO-15765-4 CAN 500 kbit (11/29-bit), `ATSP8/9/A` = CAN 250 kbit. The schema only carries the baud rate (`bus_speed`); 11- vs 29-bit is derived by the firmware from the id value (`> 0x7FF` = extended).
- **PCI length byte**: WiCAN request strings are pure request bytes (e.g. `220101`); the ELM layer prepends the ISO-TP single-frame PCI length byte. Converted `poll.data` includes it (`02 22 01 01 00 00 00 00`), matching the leaf profile.
- **Frame-count digit**: a WiCAN pid string of odd length carries a trailing response-frame-count digit (ELM327 optimization, stripped before sending). It decides the byte re-basing: `1` = single-frame (+1 shift), `2..9` = multi-frame (PCI-stripped assembly). Pid strings without the digit are inferred: any byte reference > 7 forces multi-frame, else single-frame is assumed — an ambiguous case can produce wrong offsets if the ECU answers with the other layout.
- **Flow control**: `ATFCSD` maps to the poll entry's `flow_control` (zero-padded to 8 bytes; default `30 01 00 FF FF FF FF FF`), sent on the poll's request id (matches `ATFCSH` in every convertible profile; the few pids with a genuinely different `ATFCSH` are noted above). When the response id (from `ATCRA`) differs from `request id + 8`, the poll entry carries an optional `flow_control_id` = response id so the firmware can deliver flow control to those responses; firmware without support for that key falls back to `request id + 8`.
- **B64 expression limit**: expressions addressing assembled-payload bytes beyond B64 (large cell-voltage dumps) are dropped per-signal above. Use an `array` signal to reach payload bytes up to B256.
- **float32**: the firmware evaluates expressions in 32-bit float; 32-bit integer compositions (e.g. odometer `B<<24|...`) lose integer precision above 2^24, same as any converted profile relying on them.
- **29-bit requests without ATCRA**: response id of a 29-bit request is not derivable mechanically; such pids are skipped.
- **`class` signal key**: WiCAN Home-Assistant device class, kept as an extra signal key (firmware ignores unknown keys).
